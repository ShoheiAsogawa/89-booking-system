# GitHub Pages で耐えられるアクセス数（目安）

GitHub Pages の制限と、89booking の想定アクセス数を計算した結果です。

---

## 1. GitHub Pages の公式制限

| 項目 | 制限 | 備考 |
|------|------|------|
| **帯域（bandwidth）** | **100 GB/月**（ソフト制限） | 超えると安定性の保証なし。サポートから連絡が来る場合あり。 |
| 用途 | 商用・高トラフィック向けではない | 個人・プロジェクト・小〜中規模向け。 |

※ 公開リポジトリの無料プランでも 100 GB/月 です。  
※ [GitHub Docs - GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) より。

---

## 2. 89booking の 1 回あたりの転送量（目安）

GitHub から配信されるファイルのみをカウント（Google Fonts 等の外部は含めない）:

| ファイル | サイズ（概算） |
|----------|----------------|
| index.html（予約画面） | 約 49 KB |
| admin.html（管理画面） | 約 92 KB |
| paypay.png 等 | 数 KB〜数十 KB |

**1 回の「ページ表示」あたりの目安**:  
- 予約画面のみ: **約 50 KB**  
- 管理画面のみ: **約 92 KB**  
- 平均（予約 7 : 管理 3 と仮定）: **約 60 KB/回**

※ 日付変更やタブ切り替えは Supabase への API 通信が中心で、GitHub からはほぼ再読み込みしない想定。

---

## 3. 月間で「何回まで」アクセスできるか

**計算式**:  
月間帯域 100 GB ÷ 1 回あたりの転送量（KB）＝ 月間のページ表示回数（目安）

| 想定 | 1 回あたり | 100 GB/月 で耐えられるアクセス数（目安） |
|------|------------|------------------------------------------|
| 予約画面だけ | 50 KB | **約 210 万 回/月** |
| 管理画面だけ | 92 KB | **約 117 万 回/月** |
| 予約 7 : 管理 3 の混合 | 60 KB | **約 175 万 回/月** |

**計算の根拠**  
- 100 GB = 100 × 1024 × 1024 KB = **104,857,600 KB**  
- 104,857,600 ÷ 60 ≈ **1,747,627 回/月**（約 175 万回）

---

## 4. 日別・時間別の目安

| 期間 | 175 万回/月 を割り振った場合 |
|------|------------------------------|
| **1 日あたり** | 約 **58,000 回/日** |
| **1 時間あたり** | 約 **2,400 回/時間** |
| **1 分あたり** | 約 **40 回/分** |

※ あくまで「帯域 100 GB を超えない範囲」の目安です。

---

## 5. 89booking のような予約システムでの目安

- **1 患者あたり**: 予約画面を 2〜5 回程度開く想定 → 約 100〜250 KB/人  
- **100 KB/人** とすると:  
  **100 GB ÷ 0.1 MB ≈ 100 万 人分のページ閲覧/月**

| 月間の「のべ」アクセス | 帯域の目安 | 評価 |
|------------------------|------------|------|
| 約 10 万回 | 約 6 GB | 余裕 |
| 約 50 万回 | 約 30 GB | 問題なし |
| 約 100 万回 | 約 60 GB | まだ余裕 |
| 約 150 万回 | 約 90 GB | 100 GB に近い |
| 約 175 万回以上 | 100 GB 超 | ソフト制限に抵触する可能性 |

**人数でざっくり言うと**  
- 月間 **数万人** がそれぞれ数回ずつ見る程度なら、GitHub Pages の 100 GB/月 ではまず問題になりません。  
- **月間 100 万 PV 前後** が、このサイト構成での「上限の目安」と考えておくとよいです。

---

## 6. 注意点

1. **100 GB は「ソフト制限」**  
   超えたからといって即停止ではありませんが、超過が続くと GitHub から連絡や制限の可能性があります。

2. **Supabase は別枠**  
   予約の取得・保存は Supabase の API なので、GitHub の帯域には含まれません。Supabase の無料枠（月 50,000 リクエスト等）は別途確認してください。

3. **CDN（Cloudflare）を使う場合**  
   89booking.dev を Cloudflare 経由にすると、キャッシュが効く分、GitHub への直接アクセスが減り、**実質的に GitHub の帯域を節約**できます。  
   その場合、同じ 100 GB でより多くのアクセスをカバーできます。

---

## 7. まとめ

| 質問 | 答え（目安） |
|------|----------------|
| GitHub Pages の月間制限 | **100 GB（帯域）** |
| 89booking で何回まで？ | **約 150〜175 万 ページ表示/月**（約 60 KB/回で計算） |
| 日あたりの目安 | **約 5 万回/日** 程度までなら余裕 |
| 月間 数万人規模の利用 | 通常は **問題なし**。100 万 PV 前後が上限の目安。 |

小〜中規模のクリニック・サロン向け予約であれば、**GitHub Pages の帯域だけで不足することはほぼない**水準です。
