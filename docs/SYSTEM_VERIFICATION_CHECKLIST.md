# システム正常動作・確認チェックリスト

システムが正しく動いているかを確認するための手順です。**公開前**および**定期確認**で使ってください。

---

## 前提：確認前に揃えておくもの

- [ ] Supabase プロジェクトが作成済みで、`bookings` / `blocks` / `staffs` / `audit_logs` / `expenses` 等のテーブルがある
- [ ] `index.html` と `admin.html` に正しい `SUPABASE_URL` と `SUPABASE_KEY` が設定されている
- [ ] 患者向け予約画面を LINE で使う場合、LINE LIFF の設定（LIFF ID）が `index.html` に設定されている
- [ ] 管理画面用の Supabase アカウント（メール・パスワード）が 1 つ以上作成されている

---

## 1. 患者向け予約画面（index.html / LINE LIFF）

### 1.1 画面の表示
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| ページが開く | 予約画面の URL をブラウザまたは LINE 内で開く | エラーにならず、予約画面が表示される |
| スタッフ・料金が表示される | 「料金とスタッフについて」を開く | スタッフ名と料金が表示される（Supabase の `staffs` またはデフォルト料金） |
| 日付・時間が表示される | 日付を選び、時間帯を表示する | ○（空き）・×（予約不可）などが表示され、重複や時間外がおかしくない |

### 1.2 LINE ログイン（LIFF 利用時）
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| LINE ログインができる | LINE 内で予約画面を開き、LINE ログインする | エラーにならず、予約操作ができる状態になる |
| ログイン後にカレンダーが使える | 日付をタップし、時間枠を表示 | 空き枠が表示され、枠を選べる |

### 1.3 予約の申し込み
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 予約が作成できる | 空き枠を選び、氏名・電話番号・施術時間を入力して「予約する」 | 「予約完了」などのメッセージが出て、予約が確定する |
| 重複予約が防がれる | 同じ時間帯に既に予約がある状態で、同じ枠を選んで予約しようとする | エラーまたは選択不可になり、二重予約にならない |
| 予約可能期間を超えられない | 1週間先より先の日付で予約しようとする | エラーまたは選択不可になる |

### 1.4 予約の確認・キャンセル
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 自分の予約が一覧で分かる | 予約済みの枠（オレンジ等）を確認 | 自分が予約した枠が色分けで分かる |
| 予約詳細が開く | 予約済み枠をタップ | 日時・スタッフ・内容が表示される |
| キャンセルできる（当日以外） | 明日以降の予約を選び「キャンセル」を実行 | キャンセル成功の表示になり、その枠が空きに戻る |
| 当日キャンセルはシステムから不可 | 当日の予約をタップしてキャンセルを試す | 「当日は電話/LINEで連絡」などの案内が出る |

### 1.5 注意事項・規約
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 注意事項・使い方が開く | 「予約についての注意事項・使い方」をタップ | モーダルで内容が表示される |
| 利用規約・プライバシーが開く | 「利用規約・プライバシーポリシー」をタップ | 規約・プライバシーの内容が表示される |
| 同意しないと予約できない | 規約に同意せずに予約を試す | 同意が必要というメッセージなどで止まる |

## 2. 管理画面（admin.html）

### 2.1 ログイン・基本表示
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| ログイン画面が表示される | 未ログインで管理画面の URL を開く | ログイン画面だけが表示される |
| ログインできる | 正しいメール・パスワードでログイン | エラーにならず、メイン画面（予約管理タブ等）が表示される |
| スケジュールが表示される | 「予約管理」タブで日付・スタッフを表示 | 時間軸・スタッフ列・予約・ブロック・定休が正しく表示される |

### 2.2 予約の操作
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 予約を 1 件作成できる | 空きセルから「予約作成」し、氏名・電話・症状・施術時間を入力して保存 | 予約が一覧に表示され、該当セルに予約が表示される |
| 予約詳細が開く | 予約済みセルをクリック | モーダルで患者名・日時・料金・決済方法等が表示される |
| 予約を編集できる | 詳細モーダルで料金・決済方法・決済日・メモ等を変更して保存 | 変更が保存され、再表示で反映されている |
| 予約をキャンセルできる | 詳細モーダルで「キャンセル実行」 | ステータスがキャンセルになり、スケジュール上でキャンセル扱いになる |
| 繰り返し予約ができる | 「繰り返し予約」で曜日・期間を指定して作成 | 指定した日付に同内容の予約が複数作成される（重複時はスキップ等の挙動を確認） |

### 2.3 ブロック
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 単一ブロックができる | 空きセルから「ブロック」を選び、理由を入力 | その枠がブロック（斜線等）で表示され、患者からは予約不可になる |
| 一括ブロックができる | 期間・時間帯・スタッフ・理由を指定して一括ブロック | 指定範囲がブロックされ、患者画面で該当枠が予約不可になる |

### 2.4 患者検索
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 名前で検索できる | 「患者検索」タブで名前の一部を入力して検索 | 該当する予約一覧が表示される |
| 電話番号で検索できる | 電話番号の一部を入力して検索 | 該当する予約が表示される |
| 検索結果から詳細を開ける | 検索結果の行をクリック | 予約詳細モーダルが開く |

### 2.5 ダッシュボード
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| KPI が表示される | 「ダッシュボード」タブで期間を指定 | 売上合計・予約件数・平均客単価などが表示される |
| 決済別集計が表示される | 同じくダッシュボードを表示 | 現金・クレジット・PayPay 等の件数・金額が表示される |
| スタッフ別実績が表示される | 同上 | スタッフごとの予約数・売上が表示される |
| グラフが表示される | 同上 | 月間売上推移・スタッフ別割合等のグラフが表示される |
| CSV エクスポートができる | 「CSV エクスポート」を実行 | 期間内の予約データが CSV でダウンロードされ、Excel 等で開ける |

### 2.6 料金設定
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 料金設定画面が開く | 設定系の「スタッフ料金設定」を開く | スタッフごとの料金が表示・編集できる |
| 料金を保存できる | 料金を変更して保存 | 保存成功の表示が出て、新規予約時にその料金が使われる |

### 2.7 小口経費
| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|

| 経費を編集・削除できる | 登録した経費の編集・削除を実行 | 変更または論理削除が反映される |

### 2.8 新規予約の Realtime 通知

| 通知から該当予約に飛べる | 通知をクリック | 該当日付・該当予約にフォーカスまたは詳細が開く |

## 3. データの一貫性・連携の確認

| 確認項目 | 手順 | 期待結果 |
|----------|------|----------|
| 患者の予約が管理画面に出る | 患者画面で 1 件予約 → 管理画面で同じ日付を表示 | 同じ日時・スタッフで予約が 1 件表示される |
| 管理画面でキャンセルすると患者側に反映される | 管理画面で予約をキャンセル → 患者画面で該当日を再表示（キャッシュ時間経過後または再読み込み） | その枠が空きとして表示される |
| ブロックすると患者側で予約不可になる | 管理画面で枠をブロック → 患者画面で該当日・時間を表示 | その枠が ×（予約不可）になる |
| 料金変更が患者画面に反映される | 管理画面でスタッフ料金を変更 → 患者画面で「料金とスタッフ」を開く | 変更後の料金が表示される（キャッシュを考慮し、必要なら再読み込み） |

## 4. 接続・エラーの簡易確認

### 4.1 ブラウザの開発者ツールで確認（任意）
- **コンソール（Console）**: 予約画面・管理画面を操作し、赤いエラーが続けて出ていないか確認する。
- **ネットワーク（Network）**: Supabase へのリクエスト（`rest/v1/` など）が 200 や 201 で返っているか確認する。

### 4.2 Supabase ダッシュボードで確認（任意）
- **Table Editor**: `bookings` にテスト予約が 1 件入っているか、`staffs` にスタッフと料金があるか確認する。
- **Authentication**: 管理画面用のユーザーが存在するか確認する。

## 5. よくある不具合と確認ポイント

| 症状 | 確認すること |
|------|----------------|
| 予約画面が真っ白・何も表示されない | SUPABASE_URL / SUPABASE_KEY が正しいか。ブラウザコンソールにエラーが出ていないか。 |
| 「料金とスタッフ」が 0 円や空 | Supabase に `staffs` テーブルがあり、`name`・`fee` が入っているか。またはローカルで料金設定を保存しているか。 |
| 予約しても管理画面に出ない | 同じ Supabase プロジェクト（URL・キー）を使っているか。日付・スタッフを切り替えて表示してみる。 |
| 管理画面にログインできない | Supabase の Authentication で該当メールのユーザーが作成されているか。パスワードが正しいか。 |
| LINE で予約画面が開けない / ログインできない | LIFF ID が本番用か。LINE 開発者コンソールで LIFF の URL が正しいか。 |
| 新規予約の通知がこない | Supabase Realtime が有効か。管理画面を開いた状態で患者が予約しているか（同じブラウザで複数タブの場合は挙動が異なることがある）。 |

## 6. 定期確認の目安

- **毎日**: 管理画面でその日の予約一覧に目を通す。
- **週 1 回程度**: 患者画面で 1 回「予約→キャンセル」のテストをすると安心です。
- **月 1 回程度**: 本チェックリストの「1. 患者向け」「2. 管理画面」の主要項目を実施し、不具合がないか確認する。
