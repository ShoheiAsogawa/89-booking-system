# 89CENTER 予約管理システム — システム概要・第三者向け説明資料

**「どんなシステム？」と聞かれたときに使える説明資料**です。搭載機能・デザイン・技術構成を整理し、外注した場合の費用目安も記載しています。

---

## 1. どんなシステム？（一言で）

**治療院・施術院向けの「予約管理＋売上・経費管理」ができるWebシステム**です。

- **患者・お客様向け**: LINEから開ける予約画面で、日付・時間・担当者を選んで予約・キャンセルができます。
- **店舗・管理者向け**: ブラウザの管理画面で予約の作成・編集・キャンセル、スケジュールのブロック、売上ダッシュボード、小口経費の登録・一覧、患者検索、データのCSV出力まで一通りできます。

サーバーは持たず、**Supabase（DB・認証）＋ GitHub Pages（静的公開）＋ LINE LIFF** の組み合わせで、月額コストを抑えつつ運用できる構成です。

## 2. 搭載されている主な機能

### 2.1 患者・お客様向け（予約画面・LINE LIFF）

| 機能 | 内容 |
|------|------|
| **LINEログイン** | 予約にはLINEアカウントでのログインが必要。LIFFでLINE内/ブラウザから利用可能。 |
| **カレンダー・時間選択** | 日付の前後移動、日付ピッカー、30分刻みの時間枠で空き状況を表示。 |
| **空き状況の見やすさ** | ○＝空き、●＝自分の予約、×＝予約不可。スタッフ列ごとに横並びで表示。 |
| **予約の申し込み** | お名前・電話番号（必須）、症状・ご要望（任意）、施術時間（30/60/90/120分）を入力して予約確定。 |
| **予約の確認・キャンセル** | 自分の予約枠をタップして内容確認・キャンセル。当日キャンセルは案内のみ（システムでは不可の旨表示）。 |
| **スタッフ・料金の表示** | 担当スタッフ一覧、専門・役割、スタッフ別料金をモーダルで表示。 |
| **注意事項・利用規約** | 予約についての注意事項、使い方ガイド、利用規約・プライバシーポリシーをモーダルで表示。 |
| **重複・期間の制御** | 既に予約が入っている時間帯は選択不可。2ヶ月先までなど予約可能期間の制限あり。 |
| **キャッシュ** | 日付ごとのデータを一定時間キャッシュし、同一日付の再表示時はAPIを叩かず表示。 |

### 2.2 管理者向け（管理画面）

| カテゴリ | 機能 | 内容 |
|----------|------|------|
| **認証** | ログイン | メールアドレス・パスワードでSupabase Authにログイン。未ログイン時はログイン画面のみ表示。 |
| **予約管理** | スケジュール表示 | 日付・スタッフ別のグリッド。空き・予約済み・ブロック・定休・営業時間外を色・マークで区別。 |
| | スタッフ別色分け | 予約済みセルをスタッフごとにパステル/濃い色で表示。決済済みは濃い色＋白文字。同一患者の連続予約は枠線で強調。 |
| | 予約の作成 | 空きセルから「予約作成」。氏名・電話・症状・施術時間を入力。重複時間帯はエラーで防止。 |
| | 予約の編集・キャンセル | セルクリックで詳細モーダル。料金・管理者メモ・決済方法・決済日などを編集。キャンセル実行可能。 |
| | 繰り返し予約 | 同じ内容で複数日を一括作成。曜日指定・日付範囲・重複時はスキップなどのオプションあり。 |
| **ブロック** | 単一ブロック | 空きセルから「ブロック」を選択し、理由入力でその枠を予約不可に。 |
| | 一括ブロック | 期間・時間帯・対象スタッフ・理由を指定して一括ブロック。既存予約と重なる場合はブロック不可で案内。 |
| **検索** | 患者検索 | 名前・電話番号の部分一致。スタッフ・月・ステータス（予約済み/キャンセル）でフィルター。検索結果から予約詳細を開ける。 |
| **ダッシュボード** | KPI | 期間指定で「売上合計」「予約件数」「平均客単価」を表示。 |
| | 決済別集計 | 現金・クレジット・PayPay・チケット・ツケ払い・保険など決済方法別の件数・金額。 |
| | スタッフ別実績 | スタッフごとの予約件数・売上。 |
| | グラフ | Chart.jsで月間売上推移・スタッフ別割合などを表示。 |
| | CSVエクスポート | 期間内の予約データをCSVでダウンロード（Excelで開けるようBOM付きUTF-8）。 |
| **小口経費** | 経費登録・一覧 | 日付・金額・種別（入金/出金）・カテゴリ・担当・メモを登録。一覧は期間・カテゴリ・担当・キーワードでフィルター。 |
| | 経費の編集・削除 | 論理削除対応。編集履歴（監査ログ）を表示。 |
| **通知** | 新規予約のRealtime通知 | Supabase Realtimeで「bookings」のINSERTを購読。新規予約時に画面上の通知バー＋通知音。メッセージは「○○様より、〇〇に〇月〇日 10:00から1時間の予約が入りました。更新して確認してください。」形式。 |
| **監査・履歴** | 編集履歴 | 予約・経費の作成・編集・キャンセルなどを監査ログテーブルに記録。詳細モーダル内で表示。 |

### 2.3 その他・基盤

- **料金マスタ**  
  スタッフ別のデフォルト料金を管理画面で設定可能。予約作成時の料金はここから取得。
- **営業時間・定休**  
  スタッフごとの営業時間・曜日定休をコード内で設定。スケジュールに反映。
- **レート制限**  
  予約画面で連続操作を抑えるため、ローカルストレージベースの簡易レート制限を実装可能。
- **デプロイ・公開**  
  GitHub Actions で GitHub Pages に自動デプロイ。カスタムドメイン・HTTPS の案内ドキュメントあり。

## 3. デザイン・UIの特徴

### 3.1 患者向け画面（モバイルファースト）

- **フォント**  
  Noto Sans JP・Noto Serif JP・Roboto（Google Fonts）。日本語とラベル用の英字を使い分け。
- **カラー**  
  白基調、テキストは濃いグレー/黒。自分の予約はオレンジ系（#BF360C / #FFE0B2）、予約不可はグレーで統一。
- **レイアウト**  
  最大幅600pxのコンテナ。ヘッダー固定、日付ナビ・凡例・スタッフヘッダーをスティッキーで固定し、時間軸は縦スクロールのみ（横スクロール禁止）。
- **インタラクション**  
  ボタンは角丸（99px）・タップ時のスケール/透明度変化。モーダルは下から出るシート型。ローディング時は「本気で治します」などの文言＋スピナー。
- **アクセシビリティ**  
  フォームの必須/任意ラベル、プレースホルダー、注意事項のモーダルで利用方法を明示。

### 3.2 管理画面（デスクトップ向け）

- **フォント**  
  Noto Sans JP・Roboto。数値はRobotoで統一し、ダッシュボードの「数字」感を強調。
- **タブ構成**  
  予約管理・患者検索・ダッシュボード・小口経費の4タブ。タブごとに背景色を変え（グレー・ベージュ系）て視覚的に区別。
- **スケジュール**  
  テーブルは固定レイアウト。時間は左列、スタッフは列で並べ、セルは角丸。スタッフ別パステル＋決済済みは濃い色。ブロックは斜線パターン、定休・営業外はグレー。
- **通知バー**  
  新規予約時に画面上部にバー表示。スタッフ色の左アクセント（濃い色）＋バー全体はパステル。閉じるボタン・クリックで該当日・予約詳細へ遷移。
- **ダッシュボード**  
  KPIカード、決済別カード、Chart.jsのグラフ、スタッフ別リスト。期間選択・更新・CSVエクスポートボタンを配置。
- **モーダル**  
  予約詳細・予約作成・繰り返し予約・経費登録・経費編集など、オーバーレイ＋角丸のボックス。決済方法はボタン群で選択、ツケ払い等は決済日入力欄を表示。

### 3.3 共通の方針

- 角丸（8px〜16px）、シャドウ、ホバー/アクティブのフィードバックで「押せる・選べる」を明確にしている。
- 色はスタッフ別に一貫して使い、患者向けは控えめ、管理画面は情報量が多くても区切りが分かるようにしている。

## 4. 技術構成（第三者説明用）

| 項目 | 内容 |
|------|------|
| **フロント** | 単一HTML＋CSS＋JavaScript（Vue/React等のフレームワークなし）。CDNでSupabase JS・LINE LIFF SDK・Chart.jsを読み込み。 |
| **バックエンド・DB** | Supabase（PostgreSQL）。予約・ブロック・監査ログ・経費・料金マスタ等をテーブルで管理。 |
| **認証** | 患者側: LINE LIFF（LINEログイン）。管理者側: Supabase Auth（メール/パスワード）。 |
| **リアルタイム** | Supabase Realtime。`bookings` テーブルのINSERTを購読し、管理画面で新規予約を即時表示・通知。 |
| **ホスティング** | 静的ファイルは GitHub Pages。GitHub Actions で main プッシュ時にビルド・デプロイ。 |
| **開発時** | Node の `http-server` でローカル起動（例: ポート3000）。 |

## 5. セキュリティ・運用コスト（概要）

- **認証**  
  管理画面はSupabaseセッション必須。患者はLINEログイン必須。APIキーはanon（公開）キーのみクライアントに露出（設計上許容）。
- **RLS**  
  Supabase の Row Level Security の設定を推奨。入力検証・XSS対策の記載が別ドキュメント（SECURITY_AND_COST_ANALYSIS.md 等）にあり。
- **運用コスト**  
  Supabase無料プラン（月間リクエスト・DB容量等の制限あり）、GitHub Pages・LINE LIFF は無料で利用可能。コスト最適化の考え方は COST_OPTIMIZATION.md に記載。

## 6. 外注した場合の費用目安

### 6.2 工数ベースの概算（参考）

- **規模の目安**  
  - 患者向け: 約 1,200 行（HTML/CSS/JS）  
  - 管理画面: 約 3,700 行（HTML/CSS/JS）  
  - ドキュメント・ワークフロー等を含めると、**3〜6人月**程度とみなすケースが多いです。
- **単価の目安（税別）**  
  - フリーランス: 50〜80万円/人月  
  - 中小開発会社: 70〜100万円/人月  
  - 受託開発（中〜大）: 80〜120万円/人月  

**3〜6人月 × 単価** で、おおむね **250〜600万円（税別）** 程度が相場の幅になります。

### 6.3 注意事項

- 上記は「ゼロから同等システムを発注した場合」の目安です。既存システムの改修・機能追加は別見積もりになります。
- 見積もりに含めていない例: サーバー・ドメイン・LINE公式アカウント等の初期費用、保守・運用の月額、Supabaseの有料プラン移行後の費用。
- 実際の発注時は、**要件リストの確定**と**段階的な見積もり（設計→実装→テスト）**をとることを推奨します。
